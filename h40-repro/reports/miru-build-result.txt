This difference is expected because the exact production Clang 10.0.7 and all
production source inputs are unpublished, and this candidate intentionally
changes the release identity from 4.14.180-perf+ to 4.14.180-miru+.

Warnings and compatibility limits
=================================
The log contains existing device-tree compiler reg/address-cell warnings and a
nonfatal gsi_write_channel_scratch symbol-version warning. No build error was
reported.

Stock external WLAN/audio modules advertise 4.14.180-perf+ vermagic, whereas
this build advertises 4.14.180-miru+. The production OnePlus module-signing key
and certificate are also unpublished, while the stock configuration enforces
module signatures. Stock external modules are therefore not claimed compatible
with this test kernel.

The published source lacks project 19861/18961 DTS/DTBO and the production RTIC
MPGen input. This run deliberately skipped those missing production-only DTS
targets. The generated Image.gz-dtb is an audit artifact, not a reconstruction
of the production boot image's DTB field.

Boot-test status
================
Successful compilation does not establish that the kernel boots. No flashable
boot.img was produced. A test image must preserve the original H.40 boot-v2
ramdisk, cmdline, header fields, recovery DTBO, and separate boot DTB field,
replacing only the raw kernel field with arch/arm64/boot/Image.
