Miru H.40 Snapdragon LLVM 10.0.7 CRC-only result
================================================

Outcome
-------
The CRC-only vmlinux build completed, but using a compiler with the same
Snapdragon LLVM 10.0.7 banner as the stock H.40 vendor modules produced zero
CRC convergence over the v2 AOSP-Clang build.  A flashable Image was therefore
not built.

The published kernel source/configuration still does not describe the ABI used
to build the production H.40 vendor modules.  Matching the compiler banner is
not sufficient to repair that source/configuration ABI gap.

Interpretation
--------------
MODVERSIONS CRCs are generated from preprocessed exported declarations and the
configuration-visible type graph.  The zero-change result across all 11,968
common exports shows that swapping AOSP Clang 10.0.5 for this Snapdragon LLVM
10.0.7 binary does not change the ABI encoded by the published tree.

The evidence continues to point to production H.40 using unpublished or newer
headers/patches, different ABI-affecting build macros/configuration, or both.
The broad mismatch is not an audio-only or FastRPC problem, and bypassing
MODVERSIONS would hide real type/layout incompatibilities rather than fix them.

Next evidence-based step
------------------------
Recover the production kernel's exported CRC table from the original H.40 boot
kernel (__kcrctab plus its symbol-name mapping), or obtain the production
Module.symvers/build manifest.  That table can be compared against the two
source trees to identify which declaration families diverge before another
boot image is built.  The Reno sibling source is useful as a patch candidate
only after those stock CRC differences identify the relevant headers.
