Why bypassing MODVERSIONS is rejected
-------------------------------------
The mismatch spans module, mutex, device, allocator, OF, DMA, regulator,
regmap, ALSA SoC, networking, firmware, input, PM, and other structures and
interfaces. Globally accepting these CRCs would allow modules compiled with
potentially incompatible structure layouts to execute in kernel context. A
boot obtained that way would not establish compatibility and could corrupt
memory before producing a useful diagnostic.

New toolchain evidence
----------------------
The shipped H.40 kernel banner and all supplied vendor modules identify a
Qualcomm Snapdragon LLVM 10.0.7 compiler. The Miru v2 build used AOSP
clang-r377782c, which identifies itself as Android Clang 10.0.5. MODVERSIONS
CRCs are generated from compiler-preprocessed type declarations, so the exact
compiler frontend remains a plausible contributor and must be tested before
attributing every CRC difference to missing C source.

A public third-party mirror was located at:

  sticpaper/Snapdragon-LLVM-ARM-Compiler-10.0.7-for-Android-NDK
  commit: a16fec82a8deaf8f742ea54f8de98c021af200d4
  bin/clang SHA-256:
    453971166fa1b628df189e602f355cb2c58c12cd289515400ee6260c9a83459d

The cloned binary contains the expected version strings and the repository
contains Qualcomm release notes and notices, but the mirror is not an
authoritative Qualcomm distribution and no authoritative checksum has been
found. It has been inspected without execution.

Next controlled test
--------------------
If use of that unverified mirror is accepted, first build only the generated
configuration and Module.symvers with the same source and all other recorded
inputs. Compare its 962 relevant core CRCs with the vendor expectations before
producing another boot Image. A large CRC convergence would justify one clean
v3 kernel build. No convergence would prove that the remaining incompatibility
is source/configuration ABI drift rather than the 10.0.5 compiler substitution.
